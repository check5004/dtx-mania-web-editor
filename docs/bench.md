# 耳コピ精度テスト

原曲からドラムの打点を推定する方式（候補チップ・TAB補完の根拠・自動採譜）の当たり具合を、同じ物差しで比べるための仕組みです。
「作ったが使えない」を繰り返さないよう、方式を変えるたびにここで点数を出してから画面に載せます。

- 測るページ: `bench.html`（公開版は <https://check5004.github.io/dtx-mania-web-editor/bench.html>）
- まとめて回す: `npm run bench -- <曲フォルダ> [--full 曲名]`（ヘッドレスの Chromium で同じページを動かし、`bench-results/` に JSON と Markdown を書く）。`--complete` を付けると [TAB補完](#tab補完) を測る
- コード: `src/bench/`

曲のデータはブラウザの中だけで使い、どこにも送りません。テスト曲そのもの（著作物）はリポジトリに入れません。

## テスト曲の作り方

曲フォルダの譜面のうち、ドラムのチップがいちばん多いもの（ふつうは MASTER）を正解にします。DTX は「ドラムの音（チップ）」と「BGM」が分かれているので、混ぜ方を変えて次のテスト曲を作ります。

| 混ぜ方 | 中身 | 正解 | 分かること |
| --- | --- | --- | --- |
| ドラムだけ | 譜面のドラムの音だけ | 譜面（完全に正しい） | BGM に邪魔されないときの上限。楽器の聞き分けの力 |
| 合成 | ドラム抜きの BGM＋譜面のドラムの音 | 譜面（完全に正しい） | 曲の中でどれだけ拾えるか |
| 実録音 | ドラム抜きの BGM＋曲に付いている本物のドラムの録音（`drums.ogg` など） | 譜面（人の耳コピ） | 原曲にいちばん近い条件 |
| 原曲 | ドラム入りの BGM（原曲そのもの） | 譜面（人の耳コピ） | 実際の使い方そのもの。BGM がドラム入りと指定した曲だけ |
| ドラム無し（対照） | ドラム抜きの BGM だけ | 譜面 | ドラムが鳴っていないのに当たった分は偶然。方式の「当てずっぽうの水準」 |

- 混ぜ方はエディタの再生と同じ決まりです（#VOLUME・#PAN、ハイハットの開閉と同じチャンネルの連打で前の音を止める）。44.1kHz ステレオ。
- 音が読めないチップ（.xa など）は「ドラムだけ」「合成」の正解から外し、1割を超えるとその曲では作りません。
- 曲ごとに「BGM がドラム入りの原曲か」をページのチェック（スクリプトは `--full`）で指定します。指定の無い曲は、DTX でふつうのドラム抜きの BGM とみなします。ドラム入りの曲では「合成」（ドラムが二重になる）と「ドラム無し」は作りません。

## 採点

- 楽器は採譜の研究でふつうの5種にまとめます（ADTOF などのモデルの出力と同じ）。
  - BD = バスドラム・左バスドラム、SD = スネア、TT = ハイ・ロー・フロアタム、HH = HHクローズ・HHオープン・左ペダル、CY = 左右シンバル・ライド
- 同じ種類でほぼ同時（10ms 以内）のチップは1打にまとめます（HHクローズと左ペダルが同時、など）。
- 種類ごとに、正解と推定をずれが許容幅（既定 ±50ms）以内のものどうしで1対1に組にします。±50ms は BPM150 の16分音符の半分で、グリッドに吸着して置いたときに同じマスになるくらいです。
- **適合率** = 推定のうち当たった割合（候補を採用して合っている割合）、**再現率** = 正解のうち拾えた割合、**F 値** = 両方の調和平均（0〜1、1が満点）。
- 曲をまたいだ「まとめ」は、当たり・正解・推定の数を足してから計算します。
- 曲ごとの結果には、レーン（HHC・LP・RD など）ごとに拾えた割合と、当たった組の平均のずれも出します。

## 新しい方式の足し方

`src/bench/methods.ts` の `BENCH_METHODS` に `{ id, label, note, run }` を足します。`run` はステレオの音（44.1kHz）を受け取り、`{ t: 秒, cls: 'BD' | 'SD' | 'TT' | 'HH' | 'CY' }` の一覧を返します。同じテスト曲で方式どうしが使い回す計算は `cache` に置けます。

## TAB補完

エディタの TAB補完（打った小節の先1〜4小節を点線で出す）が、どれだけ当たるかを測ります。ページの「TAB補完を測る」、スクリプトは `npm run bench -- <曲フォルダ> --complete`。コードは `src/assist/complete.ts`（予測）・`src/assist/measureAudio.ts`（原曲の聞こえ方）・`src/bench/complete.ts`（測り方）。

### 測り方

- 打ち終わった譜面を「前から順に打っている途中」とみなします。小節 m ごとに「m より前だけ打ってある」譜面から先の4小節を予測させ、譜面の続きと比べます（曲フォルダの譜面を難易度ごとに全部使う）。
- チップはチャンネルと小節の中の位置が同じなら当たり（WAV＝強さは見ない）。
- **出した**＝正解が空でない小節のうち点線を出した割合、**そのまま**＝出した小節のうち正解とまったく同じだった割合（Tab だけで済む）、**F**＝チップの適合率と再現率の調和平均、**手間の減り**＝全部採用して直したときに減るクリックの割合（(当たり−外れ)÷正解のチップ）。
- 原曲の聞こえ方は、曲に付いている音（BGM、ドラムの録音があれば重ねたもの）から作ります。

### 予測のしかた

候補はどれも、この曲でもう打った小節を写して作ります（ドラムの譜面は曲の中で何度も繰り返すため）。

1. **前回の続き**：直前の1〜4小節と同じ・似た並びの所を前から探し、そのときの続きを写す（「直前の小節を続ける」「2小節の繰り返し」もこの特別な形）。
2. **曲の構造**：原曲で先の小節と同じに聞こえる、打ってある小節を写す（2番のサビ＝1番のサビ）。小節ごとに拍の和音（クロマ）・拍の音色（20帯域の音量）・16分ごとの8帯域の立ち上がりをまとめ、同じ長さの小節の平均を引いてから似ている度合い（コサイン）を出す。
3. 候補ごとに、直前の並びの一致（1〜4小節前）・原曲の似ている度合い（予測する小節・次の小節・直前の小節）・何小節前か・4小節や8小節の区切りがそろうか、の12個の数から、「次の小節がそのまま正解になる確からしさ」をロジスティック回帰で出す（6曲23譜面で学習）。これが札の「見込み」。
   ドラムの採譜ができていれば、さらに「候補が、原曲で聞こえるバスドラム・スネア・タムとどれだけ合うか」と「直前の打ってある小節がどれだけ合うか」を足す（[下](#採譜を足したとき2026-11-03段階3)）。
4. 2小節目からは、予測した小節を打ったことにして1小節ずつ続けて予測する（変わり目で写す元を選び直せる）。見込みが基準を下回ったら止める。
5. 写す元が無い変わり目は、押したときだけ AI（フレーズ候補）に頼む。

読み取れること:

1. **いつも出すと当たらない。** 直前の小節を写すだけ（Ctrl+D）では次の小節がそのまま正解なのは 13%。曲の構造を使っても 35% で、いつも点線を出すと3回に2回は直すことになる。
2. **見込みは当てになる。** 見込み 0.5 以上なら 3回に2回、0.35 以上でも半分以上がそのまま正解で、外れてもチップの F は 0.8〜0.9 台（少し直すだけ）。そこで、見込みが基準以上のときだけ出す。エディタの既定（ふつう）は 0.35 で、点線は2小節に1回ほど出て、出した小節の 56% がそのまま正解（F 0.91）。控えめ（0.5 以上）は 5小節に1回ほど・約3分の2が正解、多め（0.2 以上）は3小節に2回ほど・約半分が正解。
3. **原曲が効く。** 原曲の聞こえ方を足すと、次の小節がそのまま正解の割合が 29% → 35% に上がる。ドラム抜きの BGM だけでもほぼ同じ（35%）。
4. **写すやり方の限界は 55%。** 正解を見て写す元を選んでも、次の小節が打ってある小節のどれかとまったく同じなのは 55%（初めて出てくるフィルなど）。そこから先は、原曲から音を採る（段階3）か AI に頼むしかない。

### 採譜を足したとき（2026-11-03、段階3）

ドラムの採譜モデル（[上](#2026-11-03-段階3ドラムの採譜モデルadtofブラウザ内)）の打点を、候補の点数に足しました。小節ごとに、候補（または直前の打ってある小節）のバスドラム・スネア・タムのチップと、採譜の打点を ±50ms で組にした F 値を出します（`src/assist/heard.ts`）。ハイハット・シンバルも入れた5種で測ると、候補選びが当たりにくくなりました（採譜が拾いきれない細かい刻みに引きずられる）。

重みは、原曲があるときの点数（上の12個の重みで出したもの）に「候補の合い方」「直前の小節の合い方」の2つを足したロジスティック回帰で学び直し、各小節で一番の候補の見込みが実際にそのまま正解だった割合に合うよう較正しました。2つの重みはほぼ同じ大きさで逆向き（+1.95・−2.02）で、効いているのは「直前の小節より、候補の方が聞こえるドラムに合うか」です（この辺りで採譜がどれだけ譜面に合うかは曲や場所で違うため）。

| 方式 | +1 | +2 | +3 | +4 | 次の小節の F（適合/再現） | 手間の減り |
| --- | --- | --- | --- | --- | --- | --- |
| 曲の構造も使う（原曲） | 35%（100%） | 30%（100%） | 25%（100%） | 23%（100%） | 0.75（0.74/0.76） | 49% |
| 聞こえるドラムも使う（採譜） | 37%（100%） | 30%（100%） | 25%（100%） | 23%（100%） | 0.78（0.77/0.78） | 55% |
| TAB補完（採譜なし・基準 0.35、v0.8.0） | 56%（46%） | 50%（36%） | 49%（27%） | 50%（23%） | 0.91（0.91/0.91） | 40% |
| **TAB補完＋採譜（エディタと同じ・基準 0.35）** | **57%（51%）** | **53%（40%）** | **53%（32%）** | **54%（25%）** | **0.93（0.93/0.93）** | **46%** |

曲ごとに1曲を外して学習・較正し直したとき（交差検証）も、基準 0.35 で 出した割合 44% → 49%、そのまま正解 56% → 57% と同じ向きでした。控えめ（0.5）は 26% → 30%（正解 63% → 62%）、多め（0.2）は 65% → 68%（49% → 49%）。

読み取れること:

1. **効き目は小さいが、同じ当たり方で出る小節が増える。** 基準 0.35 で、点線が出る小節が 46% → 51%、手間の減りが 40% → 46%。そのまま正解の割合はほぼ同じ（56% → 57%）。
2. **限界は「写す」やり方の方。** 採譜は「どの小節を写すか」を選び直すのに使うだけなので、打ってある小節に無い並び（初めてのフィルなど）は出せない（上限 55%）。そこを埋めるには、採譜の打点そのものを譜面にする必要がある。

### 原曲との照合（点線のオレンジの枠）

v0 の打点検出（原曲の3帯域の打点、感度 0.5、±50ms）で、予測した点線のチップの近くに同じ種類の打点があるかを見ました（見込み 0.2 以上の予測、次の小節）。当たり外れを見分けられたのはスネアだけでした: 打点の無いスネアの予測は当たり 33%（143個）、打点のあるスネアは 90%。バスドラム・ハイハットは差が小さく、シンバルは逆向き。そこで v0.8.0 では、原曲でスネアが聞こえない点線のスネアだけにオレンジの枠を出しました。

段階3で採譜モデルの打点に替えて測り直しました（2026-11-03、曲の構造も使う・見込み 0.2 以上・次の小節。各セルは「聞こえる と言ったチップの正解率 / 聞こえない と言ったチップの正解率（数）」）。

| 照合 | BD | SD | TT | HH | CY |
| --- | --- | --- | --- | --- | --- |
| v0（3帯域の打点） | – | 89% / 54%（2,991 / 154） | – | – | – |
| 採譜モデル | 96% / 60%（2,523 / 303） | 97% / 49%（2,521 / 624） | 86% / 41%（203 / 244） | 91% / 78%（1,404 / 1,124） | 90% / 76%（1,243 / 585） |

採譜モデルでは、バスドラム・スネア・タムで「聞こえない」と言ったチップの正解率が 4〜6割まで下がり、聞こえるチップ（9割前後）とはっきり分かれます。スネアでは外れたチップの約8割に枠が付きます（v0 は約2割）。ハイハット・シンバルは聞こえないと言っても8割近くが正解で、枠を出すと正しいチップばかりに付くので出しません。採譜ができたら、バスドラム・スネア・タムにオレンジの枠を出します（採譜を切っている・まだのときは v0 でスネアだけ）。


## 表示の時刻（譜面のチップとのずれ）

2026-11-03、「ステムのスペクトルと採譜の打点が、グリッドに置いたチップより少し後ろに見える」という指摘を受けて、譜面の右の列に出すものがチップの時刻からどれだけずれて見えるかを測りました。正解の譜面つきの3曲で、エディタと同じ 48kHz の読み込み（Chrome の変換を通す）にしています。「合成」は BGM＋譜面の音なので正解の時刻がぴったり分かり、コードのずれだけが出ます。数字はずれの中央値（＋は後ろ＝譜面では上に見える）。

| 表示 | Mephisto | なにが悪い | 忘れてやらない |
| --- | --- | --- | --- |
| 原曲の打点（ドラムの採譜） | 0.0ms | −0.5ms | −0.4ms |
| スペクトルの立ち上がり（ドラム強調）：スネア / タム / ハイハット | −2.5 / −3.1 / +4.2ms | −2.0 / +1.3 / −0.7ms | −1.9 / +4.7 / –ms |
| スペクトルの立ち上がり：キック | +12.2ms | +10.2ms | +8.7ms |
| スペクトルのいちばん明るい所：キック / スネア | +30 / +5ms | +31 / +2.5ms | +30 / +6ms |

- **採譜の打点とスペクトルの立ち上がりは、チップの時刻に ±5ms で合っています。** キックだけ立ち上がりが 10ms ほど後ろなのは、低い音を 46ms の窓で測るため（窓の真ん中をその時刻にしている）。明るい所は音の伸びの分だけ後ろに出ます（キックは 30ms ほど）。
- 「立ち上がり」はその太鼓の帯が明るさの山の半分を越えた時刻、「明るい所」は山の時刻。前後 120ms に他の打点が無いチップだけで測りました（忘れてやらないのハイハット・シンバルは BPM 184 で前後の音と重なるので外した）。
- 音の読み込みでもずれません。MP3 の頭の無音（エンコーダの遅れ 1,105 サンプル）は Chrome が正しく削り（ffmpeg で読んだものと 0 サンプル差）、44.1kHz と 48kHz の変換（読み込み時・採譜に渡すとき）も 0 サンプル差でした。

**直したもの（v0.10.2）。** 原曲の3帯域の打点（採譜を切っているときの「原曲の打点」）と、テンポ合わせの道具が、キックで後ろにずれていました。低域の帯はフィルタの遅れ（片道の IIR）と、キックの低音が大きくなるまでの時間（50Hz の1周期は 20ms）の分だけ、立ち上がりの山が遅れます。フィルタを往復でかけ、低域の立ち上がりを 10ms 前へずらして、中域・高域とそろえました（BPM の推定はずらす前の立ち上がりのまま）。

| 合成（正解がぴったり分かる） | 直す前 | 直した後 |
| --- | --- | --- |
| 3帯域の打点：低域（キック） | +17〜+20ms | +2〜+6ms |
| テンポ合わせ：小節の頭のクリックを吸いつける所（±25ms） | +16〜+20ms | +2〜+5ms |

本物のドラムの録音（実録音・録音のドラムだけ）では、採譜の打点を基準にして 吸いつける所が +0〜+12ms → −3〜+1ms、拍の推定が +4〜+8ms → 0〜+5ms、低域の打点が +8〜+17ms → −5〜+8ms になりました。BPM の推定（倍・半分の選び方を含む）は3曲とも変わりません。中域・高域の打点は直す前から −2〜+3ms です。

測り方のメモ: 採譜は `transcribe`＋`drumHits`（感度50）、3帯域は `pickOnsets`、スペクトルは `spectroDb`＋`renderSpectro` を、テスト曲（`buildCase`）に掛けて、同じ種類のいちばん近い打点（±50ms）とのずれを見ています。スクリプトは残していません。

## ずれの自動チェック（譜面と原曲の打点、ステムと原曲）

v0.13.0 から、譜面のチップと採譜の打点を照らし合わせて、ずれを「原曲の打点」の見出しに出します（`src/assist/offsetCheck.ts`）。チップごとに同じ種類のいちばん近い打点を組にし（±25ms、ずれが曲の中でゆっくり変わっても追いかける）、組のずれの中央値・頭と終わり（最初と最後の1割）・6つに分けた所ごとの中央値から見立てます。

- 12ms 以上同じだけずれている → **開始位置**（BGM のチップを動かして直す）
- 後ろほどずれていき、BPM を直すとばらつきが減る（BPM が一定の譜面） → **BPM**（合う BPM は、曲の長さの中でずれが 3ms 以内に収まるいちばん短い桁で丸める）
- 所ごとのずれの幅が 25ms 以上 → **テンポの揺れ**（テンポ合わせで小節の頭を何か所か合わせる）

正解の譜面つきの3曲で、採譜した打点に対して、譜面そのまま・開始位置をずらした譜面・BPM を少し変えた譜面を測りました（「実録音」は BGM＋本物のドラムの録音、Mephisto の実録音は正しい譜面でも +10ms ずれています）。

| 譜面 | 合成（3曲） | 実録音（3曲） |
| --- | --- | --- |
| そのまま | 3曲とも「合っている」（0.0 / −0.8 / −0.4ms） | 3曲とも「合っている」（+10.0 / +0.5 / +6.1ms） |
| 開始位置 +24 / −37 / +80ms | 「開始位置」、ずれは ±0.8ms で当たる | 「開始位置」、そのままとの差は ±0.5ms で当たる |
| BPM を 0.07% 速く・0.05% 遅く | 「BPM」、元の BPM（150・122・184）を当てる | 「BPM」、150・121.99・183.99（本物のドラムの揺れの分） |

水平線（楯さんのドラムのステム、72.946 BPM で一定）から作ったグリッドどおりの譜面でも、そのまま −0.1ms、開始位置 −24ms → +23.9ms、BPM 73・72.9 → 72.946 と見立てました。BPM 72.95（丸めた値）だと、終わりで +15ms ほどずれますが「合っている」の範囲です。1回の計算は 1,000 打で 7〜9ms なので、譜面を直している間は 0.3 秒待ってから測り直します。

**ステムと原曲のずれ**（`src/audio/lag.ts`）。打点をステムから取っているときは、ステムと原曲を 1/1000 秒ごとの「音が急に大きくなった所」で重ね、いちばん重なるずらし方（±150ms）を探します。ステムがずれていると、譜面が合っていても打点がずれて見えるためです（分離ソフトが MP3 の頭の無音を足したまま書き出すと、44.1kHz で 1,105 サンプル＝25ms 遅れる）。水平線のステム5本を足した音を原曲のかわりにして測ると、ドラムのステムはそのまま −0.1ms、1,105 サンプル遅らせると +24.9ms、529 サンプル早めると −12.1ms、40ms 遅らせると +39.9ms でした。ドラムの入っていない音（ドラム以外の4本）と比べると「測れない」になります。5分の曲で 0.3〜0.5 秒かかるので、少しずつ休みながら測ります。

測り方のメモ: 3曲は `buildCase` の「合成」「実録音」を採譜し、`chipTimes` の BGM の位置・BPM を変えて `analyzeOffset` に掛けました。画面でも、原曲を BGM＋譜面の音に差し替え、BGM を 24ms ずらす → 見出しに「ずれ +25ms」→ 直すボタンで「合っている」、ドラムの音だけを 1,105 サンプル遅らせたステムを入れる → 「ステム +25ms」→ 直すと採譜し直して「合っている」、BPM を 122.085 にする → 「BPM を 122 にして合わせる」で元の BGM の位置まで戻る、を確かめました。スクリプトは残していません。
